# VisDrone DET：MATLAB 源码与 Python 评测逐项对照

本说明采用9月11日沟通中允许的替代方案（a）：锁定官方源码，逐项核对 Python 实现，补充边界用例和同一预测的重算记录。它不是一次成功的 MATLAB 运行记录，也不把 Python 自身重算一致称为跨语言数值一致。是否足以通过验收，仍请 reviewer 根据下列材料判断。

- Python：[evaluate_visdrone_det_strict.py](../../scripts/evaluate_visdrone_det_strict.py)，SHA-256 `c54f925be2c70fe90e57c123ccc7c2653e83b7800e7d8209196b5f1df6e0f460`。本次只增加审计脚本和测试，没有修改评测数值逻辑。
- 输入：原始P0第120轮 `last.pt` 的548张验证预测。沿用已公开的 [DET TXT 包](../../results/closure-evaluation/p0-locked-s20260824-stats120/predictions-det-548.zip)，不重做推理、不挑选预测。
- [机器可读审计目录](../../results/det-source-alignment-20260911/)保存官方文件的 Git blob ID、提交内/本机 SHA-256、Python 函数行号、逐输入文件哈希、测试和命令。Windows CRLF 与提交内容分别记录哈希，去除换行形式差异后再核对源码文本。

## 计算步骤的对应关系

表中 MATLAB 文件均指上面的固定提交；Python 行号对应上述哈希。显示图片的 `displayImage.m` 不参与指标计算，不在等价范围内。

| 环节 | MATLAB 源码入口 | Python 对应 | 核对结果与边界 |
| --- | --- | --- | --- |
| 图像和文件顺序 | `findImageList.m:3`；`saveAnnoRes.m:6–10` | `main:187–194`、`read:174–177` | 按文件名顺序读取；审计确认548个ASCII文件名且annotations中没有额外条目，DET文件名集合相同。图像只用于取得原始高宽。缺失文件被Python当空结果是额外容错，本次输入不依赖该容错。 |
| GT有效标志 | `saveAnnoRes.m:13–15` | `_filter_rows:41–47` | 类别0先剔出；GT第5列由0/1翻转为ignore标志。Python提前翻转不影响只读取前4列的区域过滤。仅对实际二值标志等价，审计检查全部GT。 |
| ignore区域绘制 | `dropObjectsInIgr.m:4–15` | `_filter_rows:41–54` | 区域坐标下限1；MATLAB绘制区间含两端。Python使用左端减1、右端不减1的切片，保留此像素定义，而不是普通连续bbox求交。多个区域取并集。 |
| 取整和截断 | `dropObjectsInIgr.m:19–23,37–41` | `_filter_rows:59–62` | 正数半值用floor(x+0.5)；原工具随后把各分量限制为至少1，负数舍入的差别在这一步被消除。x/y再截到图像边界，w/h不按图像边界缩小。 |
| 积分查询 | `createIntImg.m`；`dropObjectsInIgr.m:24–28,42–46` | `_filter_rows:65–68` | 原式相当于统计原坐标中的(x,x+w]×(y,y+h]，排除上、左边缘。Python直接求和这一集合；不是常见的含左上角bbox区域。 |
| ignore删除阈值 | `dropObjectsInIgr.m:28–30,46–48` | `_filter_rows:68–70` | 仅覆盖比例严格小于0.5时保留；恰好0.5删除。分母是舍入后原w×h，不是裁剪后的面积。留下的行保持原浮点bbox，不替换成查询时的整数bbox。 |
| DT与GT排序 | `evalRes.m:63–67` | `_eval_res:78–82` | DT按分数降序、GT按ignore升序；均保持同分原顺序。MATLAB的稳定排序行为与NumPy显式mergesort相对应。 |
| IoU/IoF | `compOas.m:30–47` | `comp_oas:19–32` | 连续xywh，不加1、不加epsilon。正常GT分母为并集；ignored GT分母为DT面积。宽或高交集非正直接为0，零宽高DT不会进入除法。 |
| 匹配顺序 | `evalRes.m:69–110` | `_eval_res:83–101` | 正常GT优先、正常GT最多匹配一次、ignore GT可重复吸收。等于IoU阈值可匹配；相同overlap选择遍历中后一个GT。ignore命中标为−1，不算TP/FP。 |
| 每图数量上限 | `calcAccuracy.m:21–34` | `evaluate:134–142` | 顺序是先截每图前1/10/100/500行，再筛类别，再调用匹配排序。不能改成每类别top500。导出的TXT在这一入口前已按分数排序。 |
| 跨图同分顺序 | `calcAccuracy.m:33–39` | `evaluate:141–153` | 按图像顺序拼接，再按分数稳定排序；同分检测保持图像、行的先后关系。 |
| recall分母 | `calcAccuracy.m:38–41` | `evaluate:150–155` | 分母为该类别GT行数，至少1；按源码保留其中ignored GT行，并未擅自改成只数有效GT。 |
| AP积分 | `VOCap.m:2–8`；`calcAccuracy.m:44–46` | `_voc_ap:105–111`、`evaluate:156–160` | maxDets=500时计算累计TP/FP，构造反向precision包络，在recall变化处积分；不是COCO的101点插值。 |
| IoU和均值 | `calcAccuracy.m:18,50–56` | `evaluate:130,161–170` | 10个IoU阈值覆盖.50至.95，AP75取第6个；结果乘100后以百分点表示。浮点构造和归约的最低位差异不能仅靠阅读证明完全相同，应按约定容差判读。 |
| 重复类别索引 | `calcAccuracy.m:11–15,50–56` | `evaluate:123–129,161–170` | 原码每遇到一张含该类别的图就追加一次类别编号，最终均值保留重复索引。即使这种按出现图像数加权的行为容易被误认为bug，也不在本移植中“修正”为去重类别均值。 |
| 展示值 | `evalDET.m:26–33` | JSON保留未四舍五入值 | MATLAB命令行显示到小数点后两位，Python存储完整double结果。对齐应比较计算值，不能把显示舍入当作算法差异。 |

MATLAB的[稳定排序定义](https://www.mathworks.com/help/matlab/ref/double.sort.html)和[round定义](https://www.mathworks.com/help/matlab/ref/double.round.html)另行核查。当前移植限定为本评测调用路径：不声称覆盖 `evalRes` 的cell数组接口或 `mul=1` 等未使用选项，也不声称覆盖任意NaN、无穷值或超int32范围输入。

## 测试如何支持上述对照

[test_det_source_audit.py](../../tests/test_det_source_audit.py)共29项用例，实际运行记录见审计目录的 `edge-tests.log` 和 `tests.xml`。

其中12项用固定随机seed生成ignore区域、负坐标、半值、越界和重叠输入，用另一条明确采用1-based积分递推、四角查询的测试路径，核对生产实现的直接切片求和。该测试oracle也是Python，不冒充MATLAB输出。其余用例有可手算的期望值：50%阈值、未裁剪分母、零宽高、普通GT优先、ignore复用、GT等IoU时的选择、空输入、重复检测、跨图同分、数量截断顺序、VOC包络、重复类别权重和recall分母。

审计脚本第一次把所有DT宽高大于0当作前提，前置检查失败。原预测确有零宽高行，因此改为检查非负并计数，增加零宽高的明确用例；**没有删除检测或修改原始预测**。原MATLAB与移植都在交集宽高非正时直接返回0。

## 完整数据复核与证据边界

运行 [audit_p0_det_alignment.py](../../scripts/audit_p0_det_alignment.py) 核验了实际输入域、源码和checkpoint哈希，29项测试通过，同一548份TXT的重算已完成，退出码0。完整JSON输出与原结果逐字节一致，AP/AP50/AP75/AR500分别为21.7002965900、39.3605951827、20.6083742205、38.2193707409，Python两次计算的差值均为0。

输入检查覆盖40169行GT、259831行DT，其中155行DT至少一边为零，全部保留；坐标有1042个精确半值，没有与半值相差非零但小于1e−10的坐标。原始核验结果见 `audit.json` 的 `input_checks` 和 `python_reproducibility_comparison_not_matlab`。MATLAB实际未运行，跨语言差值字段明确为null，不能把Python重算差值替代它。

按本次沟通口径，AP/AP50/AP75/AR500的跨实现微小浮点差异应小于0.01个百分点，超过0.05需要解释；0.01至0.05也应明确记录，不能默认为已对齐。现提交“源码逐项对照＋边界测试＋同预测复算”供方案（a）审核，不再把修好本机MATLAB许可证当作唯一可提交路径。
